# Pi role-dispatch pilot

Source-only pilot for strategist, coder, report-only auditor, read-only scribe (`/explain`), optional two-file concierge child (not used by `/sync`/`/handoff`) and a bounded four-child read-only advisory council (`/council`). It is not installed into any user-level Pi, Claude, or Codex directory.

## Setup

Requires Pi 1.4.0+, Node.js 22.19+, and credentials for the models you select. Copy [`tests/fixtures/pi-role-policy.json`](../tests/fixtures/pi-role-policy.json) to a **private file outside the public source tree**, substitute your own five exact `provider/model` IDs and three role assignments, then set `PI_ROLE_POLICY_PATH` to its absolute path. Missing or invalid policy prevents the extension from loading; no ambient model is selected as a fallback. The public fixture retains the three-role baseline for compatibility. To enable `/explain`, add a `scribe` role to your **private** policy with an already allowlisted exact model, `thinking: "low"`, and `tools: ["read", "grep", "find", "ls"]`; without it the role dispatch stops. For source-only `/sync` and `/handoff` in a trusted disposable project, add a `concierge` role with an allowlisted exact Haiku model, low thinking and exactly `read,grep,find,ls,edit,write`; its child receives a fixed root, the explicit guard, no shell, and requires a bounded main-captured `Artifacts/Temp/*.json` Git/parity evidence file (stdout/stderr/exitCode, ≤64 KiB). Do not put API keys in the policy.

For a local Git Bash session, after creating your private policy at the example path:

```bash
export PI_ROLE_POLICY_PATH="$HOME/.pi/agent/role-policy.json"
pi -e ./pi/extensions/guard.ts -e ./pi/extensions/session-observability.ts -e ./pi/extensions/role-agent.ts
```

Run Pi from a trusted pilot project; point all three `-e` flags to absolute source paths when outside this repo. The parent loads the guard and bounded session observability explicitly; shell/write-capable role children receive **only** the guard, with ordinary extension discovery disabled. The report-only auditor retains its no-shell/no-write tools. Observability reads `Artifacts/.agent/current_task.md` once per session (≤2,000 B) when present; it does **not** validate that file's age, so verify its objective against the active TODO before acting. It writes completed-tool **metadata only** to an existing project's `Artifacts/.agent/pi-audit.jsonl` (64 KiB cap, recent validated rows retained). It records tool type/outcome/time, never command, tool arguments, file path or result content; it does not audit user-typed direct shell or child-internal calls and adds no automatic completion nag. This is a source-only preview, not a global installation or OS sandbox. `/pi-roles` shows the loaded private assignments. Ask Pi to call `pi_role_agent` with `{"role":"strategist","task":"Plan a bounded change"}`; the other roles include `coder`, `auditor`, `scribe`, configured `concierge`, the explicit `council-perspective` route, and `pi_council` (three perspectives plus advisory synthesis).

## Pi prompt templates (source-only preview)

`prompts/{blueprint,implement,audit,explain,council,triage,grill,registry-audit,snapshot,sync,ingest,learn,clean,graduate,skill-graph,sweep,agents-md,docs,handoff}.md` can be selected for one Pi process with repeated `--prompt-template <absolute-source-path>` flags. They are **not installed** into your user-level Pi prompts. In a disposable consuming project, load the pilot extension with `-e <absolute-path-to-role-agent.ts>`, set the private policy environment variable, and add only the templates you are testing. Then invoke a selected `/name` command in Pi. `/blueprint`, `/grill` request a strategist child; `/implement`, `/triage` request a coder child; `/audit`, `/registry-audit`, `/snapshot` request a report-only auditor child with main-session captured evidence. `/explain` requests a read-only scribe child and its `codebase-navigator` skill; the child must be observed, not inferred from the template. `/sync` and `/handoff` run in the main session on a real project (no child; they replace the legacy `source-command-sync`/`source-command-handoff` skills, which can be excluded in Pi settings); `/ingest`, `/learn`, and `/clean` remain main-session workflows; `/clean` requires explicit confirmation before any deletion. `/graduate` is source-repo-only and report-first, `/skill-graph` uses a strategist, and `/sweep` uses only configured pilot child roles plus a main-session docs scan. `/agents-md` is the Pi report-only successor to Claude's `/claude-md`; it does not invoke the Claude plugin. `/docs` updates *repository* docs with `doc-updater` in the main session, not the separate user-level `/skill:docs` connector. Pi `/handoff` is **local-state-only** by user decision: it writes the current-task pointer (≤2,000 UTF-8 bytes), the brief (≤16 KiB) and, for a real decision, the decision log, then reports backup pending. TODO `[x]` markers, commit/push and backup remain outside it. GitHub backup is a separate authorized action; the existing Claude/Codex `/handoff` push requirement is unchanged. If the extension is missing, child-routed templates must stop rather than claim a role was dispatched.

A project-local `AGENTS.md` and optional Pi global context are separate from prompt templates. The global proposal lives in `Pi-global.md` at this repo's root; it includes eight **Pi-specific common-rule summaries**, not auto-loaded copies of Claude `rules/common/`. In a disposable consumer, explicitly preview that source file with `--append-system-prompt <absolute-path-to-Pi-global.md>`; without that flag the preview is absent. Neither it nor these templates is installed by this source pilot. Raw test output and exit status must be retained by the main session in a file the auditor actually reads, including for an audit following `/implement`; only an explicit project authority rule permits transcribing the auditor's cited PASS into a TODO marker. Do not use legacy `/skill:source-command-*` wrappers as evidence of Pi-native isolated routing.

The manuscript pilot loads one selected skill in an explicitly trusted disposable project and not in an untrusted or control project; it does not install the package globally or validate editorial behavior. `code-mcp`, `geometry`, and `manuscript` have source-only opt-in/control checks. ## Workflow

`extensions/role-agent.ts` registers one tool and one inspection command. `lib/role-policy.mjs` loads and validates the private policy; `lib/role-runner.mjs` starts a separate Pi process for each role, setting the exact provider/model, thinking level, and tool list. It checks the completed assistant message's **reported** provider/model and thinking level, aggregates usage across turns, and rejects mismatches. That observation does not prove the provider applied a particular reasoning budget.

Before requesting an audit, the orchestrator runs the appropriate tests, captures the **raw output and exit status** in a file accessible to the auditor, and gives the auditor that file path plus the code paths to inspect. The auditor can read evidence and source but has **no `bash`, `powershell`, `edit`, or `write` tools**. It must return INCOMPLETE if evidence is missing or stale; it cannot rerun tests itself. The coder still has shell and write access.

## Council routes (source-only advisory)

`/council <question>` requests the `pi_council` tool after the main session supplies **one** regular, single-link synthetic evidence file in a trusted disposable project's `Artifacts/Temp/` and its lowercase SHA-256. The tool sequentially invokes strategist, coder and auditor read-only perspectives, then a separate GPT Sol/high read-only strategist-profile synthesis. It refuses absent/changed evidence, missing/oversized outputs and synthesis without GO/NO-GO, three perspective labels and an explicit disagreement. Each of at most four children has a ≤10-minute timeout; the session budget is ≤40 minutes. The synthesis is advisory, not an independent audit or a decision. Tool allowlists are not OS sandboxing; no decision-log, TODO, source or deployment authority follows from the verdict. The synthesis output is limited to 16 KiB and cites three independently obtained texts; citing labels is a structural check, not proof the reasoning is sound.

The lower-level perspective route is also available:

Call `pi_role_agent` with `role: "council-perspective"`, one `perspective` (`strategist`, `coder` or `auditor`), `task` as the question, an absolute `evidencePath` directly under a trusted disposable project's `Artifacts/Temp/`, and the **same** lowercase `evidenceSha256` for all three calls. Each call gets the existing private model/thinking binding but a fixed `read,grep,find,ls` profile; the normal coder remains writable outside this route. The source validator checks a regular single-link ≤64 KiB evidence file against the supplied hash before and after the call, and the runner requires a successful observed read of that exact path. The perspective contract is `pi/agents/council-perspectives.md`; do not infer a council synthesis, GO/NO-GO, task completion or decision-log change from three opinions. The bounded T7 route above owns synthesis. This is **not** OS isolation: reads remain unrestricted, provider credentials are inherited, and concurrent file replacement can race the hash check.

## Concierge write gate (source-only routed pilot)

`pi/lib/concierge-guard.mjs` supplies the two-file write check used by `pi/extensions/guard.ts` **only when** the concierge dispatcher sets `PI_ROLE=concierge` and `PI_CONCIERGE_ROOT` to an absolute, real project root before child launch. Missing or invalid root under that role marker denies writes and shell, never falling back to the parent guard. A child cwd that resolves to a different root also denies writes. The source-only T4 dispatcher sets both values and requires `pi/lib/concierge-evidence.mjs` to validate the main-captured Git/parity facts before dispatch; the default three-role fixture still has no concierge. With that scope active, only `edit`/`write` to `Artifacts/.agent/current_task.md` or `Artifacts/HANDOFF_BRIEF.md` pass; shell and unknown tools are denied. Existing regular files must have one link and canonical spelling; symlinks, junction parents, hardlinks, directory targets and path aliases are rejected. Read tools remain unrestricted. This is a pre-tool check, **not** atomic with Pi's later write: a concurrent filesystem replacement can race it (TOCTOU). It does not contain child credentials or OS-level writes, and must only be exercised with synthetic data in trusted disposable projects. No global install or live role route is authorized; synthetic-project probes are not a production safety guarantee.

## Limits

- This is a pilot, not a migration of all commands, rules, skills, plugins, or hooks. A disposable Pi parent invoked the extension's `pi_role_agent` tool for a read-only scribe `/explain` and received a cited child result; a separate direct-child probe observed the configured private binding and read-only tool events. Earlier three-role fixture flow was driven through `runRole()` directly, not through the extension as a multi-agent workflow. Neither probe proves production reliability or full scribe documentation/editing work.
- A tool allowlist and the Pi guard are **not a security sandbox**. `read`, `grep` and `find` can access sensitive files beyond the task unless the operating environment restricts them; their contents may reach the provider. The scribe pilot is tested only in trusted disposable projects with synthetic, non-secret data. Model subprocesses inherit the Pi process environment, including credentials used to call their providers. The coder has `bash` and can access inherited keys; run only trusted tasks and projects. The guard sees Pi `tool_call` and user `!`/`!!` (`user_bash`) in processes that load it; it does not inspect shell scripts after launch, indirect writes or unguarded external processes. Dangerous direct shell asks for confirmation with a UI and denies without one. Keep stronger isolation in scope before global or unattended deployment.
- **Write scope (PI-2 B1):** the guard blocks `write`/`edit` whose resolved real path (links and junctions followed, new leaves checked through their nearest existing ancestor) is outside the launch directory, except the OS temp directory; UNC/extended paths and ambiguous dot/space segments are refused without touching the filesystem. Shell commands are **not** sandboxed. PI-2 S-B denies only the common destination operand of `cp`/`mv`/`install`/`rsync`/`ln`/`tee` when it resolves outside the launch directory or OS temp; interpreters (`python -c`, `node -e`), `$VAR` destinations, `xargs`/`find -exec` wrappers, hard links, TOCTOU and any other program that writes still escape it, and the complete fix is an OS-level container or sandbox. Uncovered: redirects to non-source paths, plain `rm`, non-777 `chmod`/`chown` and recursive deletes of any absolute path outside the project (not only under `/tmp`) stay uncovered. Paths are judged by mirroring Pi's own normalization (Unicode spaces, `@`, Windows Git Bash/MSYS/Cygwin/WSL drive forms, `~`, `file://`) and lexical resolution against the launch directory, then compared by real path; the filesystem is first touched only for the local launch and temp directories and the nearest existing ancestor of a non-UNC target. Residuals: a hard link inside the project that points outside is not detected; `TMP`/`TEMP`/`TMPDIR` define the temp exemption; a launch directory on a network drive or an extended-length `\\?\` path fails closed. A session that must edit another repository has to be launched there.
- The auditor's lack of shell prevents independent test reruns. A caller-supplied summary is not evidence: it must read captured raw output and compare it with the source itself.
- The runner uses a ten-minute default child deadline and a two-second force-kill grace period; actual multi-minute and cancellation behavior has not been production-tested. An isolated Pi agent-directory preview and byte-for-byte rollback have been exercised; **live** private-policy installation, user-level instruction loading, rollback and cross-project behavior have not been implemented or audited.
