Implement `$ARGUMENTS` only after checking the approved task, prerequisites, scope, and acceptance check. Use `pi_role_agent` with `role: "coder"`; give it the exact task, allowed file paths, requirement to write a failing test before production code, verification command, and instruction to report changed paths and actual output. The main session reviews the diff and independently runs fresh checks; a coder's DONE is not an audit PASS. Before requesting a separate auditor child, the main session must capture the full raw test output and exit status in a readable evidence file outside the coder's allowed source-edit scope; pass its path to the auditor and require the auditor to read that path. Pasted excerpts, hashes, or a coder's summary are not substitutes: if the file is missing or stale, return INCOMPLETE. Do not mark `[x]` unless a separate read-only auditor has issued a cited PASS **and** an explicit project task-authority rule permits the main session to record that exact marker; when no such rule exists, leave the TODO unchanged even after PASS. If the Pi role extension/private policy is unavailable, stop rather than treating main-session work as an isolated coder run. No commit, push, deploy, or user-level overwrite without separate authorization.
