# Pi visual-storytelling bridge — explicit project-scoped preview

Use this only with the selected `visual-storytelling` local package. Pi gives each loaded skill an absolute `location` (the path to `SKILL.md`). For `pptx-slide-design`, a command in the skill containing `${CLAUDE_PLUGIN_ROOT}/skills/pptx-slide-design/scripts/<name>` is Claude-only syntax: Pi does **not** substitute that token. Resolve the named `scripts/<name>` against the parent directory of the loaded skill's location, verify that exact file exists, then use its absolute path if and only if the task actually needs validation. Its `references/` and `data/` are resolved against that same skill directory, never the consuming project's cwd. If the location or requested file is missing, stop; do not run a guessed script or assert validation passed.

The `creative-director` child is **not configured** in the Pi pilot. Skill discovery does not author a layout spec, render a slide, or dispatch a specialist. Use the main session for a user-approved layout brief; only the report-only auditor may review captured evidence when explicitly routed. Do not claim that loading this bridge installs anything globally. Project trust and tool allowlists are not an OS sandbox.
